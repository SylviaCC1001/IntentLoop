# IntentLoop 信息层级规范

> 这份规范是 UI/交互重构的「标尺」。任何页面、任何新 feature 上线前，
> 先用这把尺子量一遍：每个模块该放在哪一层？放错层 = 平铺过重。

## 一句话原则

**一个东西放在哪一层，由「访问频率 × 是否需要和主体并排」决定，
不由「它重不重要」决定。**

评审台账、版本记录都很重要，但重要 ≠ 必须平铺在主页面。
重要的东西放错层级，照样让页面失去主次。

---

## 四层容器模型

| 层级 | 容器 | 准入标准 | 典型归属 |
|------|------|---------|---------|
| **L1 主体** | 页面主内容流 | 高频 + 是这个页面的「主语」 | PRD/原型资产卡、看板三列、文档正文 |
| **L2 抽屉 Sheet** | 侧拉 / 底拉抽屉 | 中频 + **需要和主体并排看或来回切** | 版本历史、评审台账 |
| **L3 弹窗 Dialog** | 居中模态 | 低频 + **一次性、不需要看主体** | 上传、创建、删除/回滚确认 |
| **L4 折叠 / 降级** | Accordion / 紧凑网格 / Popover | 低频 + 辅助信息，平时不用看 | 附录列表、方案描述、统计 meta |

---

## 三条铁律（违反即「平铺过重」）

### 铁律一：一个页面只能有一个 L1 主语
确定页面的「主语」，其余模块一律降级。
- 方案详情页主语 = **资产（PRD + 原型）**
- 评审台账、版本记录、附录都不是主语，出现在 L1 就是错的。

### 铁律二：Sheet 与 Dialog 不能混用，看「要不要并排」
- 需要边看主体边操作 → **Sheet**（版本对比要看当前内容、评审定位要跳文档）
- 纯一次性输入 / 确认，不看主体 → **Dialog**（上传、创建、确认）

### 铁律三：统计数字不占卡片，占「条」
数字是「扫一眼」的信息，不配拥有独立卡片。
- header 多个 stat 大格子 → 压成一行紧凑 meta 条 + badge
- 列表顶部的装饰性大标题（如 "Review Ledger" 占位）→ 删

---

## 入口收敛规范

L2 / L3 / L4 的模块从 L1 拿走后，必须在主体留一个**轻入口**，
否则就是功能丢失。入口三种形态，且必须「小到一行」：

- **数字徽标入口**：`评审 5 待处理 →`（点击开 Sheet）
- **按钮入口**：`[版本历史]`（点击开 Sheet）
- **折叠头入口**：`附录 (3) ▾`（点击展开 L4）

入口做成大卡片 = 又变回平铺，禁止。

---

## 页面落地映射

### solutions/[id]（动刀最多）
- **L1**：PRD 卡 + 原型卡并排，只留「当前版本 + 操作按钮」
- **L2**：版本历史（`[版本历史]` → 宽 Sheet，装 VersionHistoryPanel）；
  评审台账（header 数字入口 → Sheet，装 ReviewIssueLedger，逻辑不动只换容器）
- **L3**：上传 / 创建（沿用现有 Dialog）
- **L4**：附录（折叠区）；header 5 个 stat → meta 条

### board（参照标杆，基本不动）
已合规：三列 kanban + 卡片只放摘要 + 点击跳详情。
可删顶部 "Review Board" 装饰性大写小标题。

### docs/[id]（预防性对齐）
版本历史同样走 L2 Sheet，不要在文档页平铺 VersionHistoryPanel 占半屏。

---

## 重构的本质（别忘了）

这次重构不是「删功能 / 做小」，是「挪层级」。
同样的版本记录，放 L1 平铺就重，放 L2 抽屉就轻——代码量一行没变，
体验天差地别。想通这点，任何新 feature 你都能自己判断该放哪层。
